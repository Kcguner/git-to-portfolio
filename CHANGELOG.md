# Changelog

All notable changes to Git-to-Portfolio are documented in this file. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and the project uses semantic versioning.

## [Unreleased]

### Fixed

- A long repository name no longer pushes its card wider than the page. The project title is a `truncate`d span, but the link around it was `inline-flex`, and an inline-level box is sized by its own content while `nowrap` text has a min-content width of the whole name — so the row took the name's full width and the text ran out past the card border and off the viewport. The link is now a block-level flex row, which its heading caps, so the name ellipsizes inside the cell. `min-w-0` on the child could not have fixed it: it clamps the child's own minimum, not the container's intrinsic one.
- The header's controls no longer wrap out of their fixed `h-9` boxes. The row needs about 1044px before the boxed action labels fit on one line, and they were shown from 1024px, so at 1024–1280px the "Home" and "Save as PDF" labels wrapped and spilled over their neighbours. The row is `whitespace-nowrap` now, and the optional items give way in the order they matter: the print and share labels, the GitHub link and the documentation link wait for `xl`, `xl` and `lg` respectively.
- The theme toggle draws the palette it switches to instead of the one already on screen, and repaints the browser chrome with it. Each branch paired an icon of the current theme with the label naming the other one, so a moon sat on the night page and read as a control with nothing left to do. The `theme-color` tag is resolved per request from the theme cookie, so a client-side toggle left the tab, the address bar and the overscroll area in the palette the visitor had just left — and a client-side navigation replayed the cached root-layout payload and put the stale colour back. The tag is now painted from the class on `<html>`, the one thing that is always current, both on press and after every route change.

- An unknown username answers `404` again, and a non-canonical login answers `308` instead of being turned into a client-side redirect. The route's `loading.tsx` fallback made Next.js commit to `200 OK` before the page resolved, and a status line cannot be taken back once the body streams: `notFound()` mid-stream can only inject a `noindex` meta tag, and `permanentRedirect()` mid-stream degrades to a browser redirect. The route-level fallback is deleted. The profile lookup and both redirects stay in the page body, ahead of every Suspense boundary, and the repository work moved into an async `ProfileRepos` component rendered behind its own `<Suspense>`, so the shell is still complete before a single repository is requested.
- Featured-language percentages are formatted with `Intl` for the page's language instead of being assembled by hand, so Turkish writes `%60` where German writes `60 %`. The bar and its accessible name carry the same string.
- The comment above the repository lookup on the portfolio page claimed the repositories still came from the Search API and quoted its rate limit. They have come from the core API for a while; the comment now describes the pinned-first lookup, the local ranking and why the core API is used at all.
- The 404 and error sheets no longer set `text-white` on the primary button. Paper white on the night theme's signal yellow falls below AA; the button class already carries the right ink for each theme.
- The home page no longer ships decorative orbs, pulsing dots or entrance animations, and nothing on it sets its own corner radius. The drawing is static and the single CSS radius governs.
- The social card a visitor shared was always in Turkish. The home page card was hardcoded Turkish and the profile card hardcoded English, so three of the four languages got a card in a language nobody on the page reads. Both are now rendered per language, with matching `og:image:alt` text.
- A failed repository lookup no longer takes the whole profile page down. A lookup failure now renders the profile card, the language block and a repository state that reports the failure, and logs the short GitHub failure code with the HTTP status once. Only a missing user becomes a 404; other upstream failures still reach the error boundary instead of being disguised as a missing profile.
- Repositories no longer load through the Search API. Unauthenticated search refuses some public accounts with `422 Validation Failed` ("the resources do not exist or you do not have permission to view them"), so a valid profile rendered with no repositories at all. It is also rate limited at 10 requests/minute against the core API's 60/hour. Repositories now come from `GET /users/:username/repos`, ranked locally by stars over the 100 most recently pushed repositories.
- A failed repository lookup no longer claims the user has no public repositories. That message was factually wrong whenever GitHub was merely unreachable, so the empty state now distinguishes a genuine empty account from a failed request.
- Profile pages render a single `<h1>` again. The page header title was demoted to a paragraph, and the profile page heading is now visible at every breakpoint instead of disappearing on small screens.
- The root layout renders the correct `<html lang>` on the server instead of shipping `lang="tr"` for every language and patching it from a client effect. `proxy.js` resolves the locale per request and forwards it internally; client-side navigation still corrects the attribute because RSC payloads do not re-render the layout.
- 404 pages emit a localized `<title>` from the server. Both not-found segments previously shipped hardcoded English titles and relied on a `document.title` mutation that fought the Metadata API and only ran after hydration.
- The 404 body no longer depends on a client component. The not-found segments read the resolved locale from the request header and render `NotFoundView` directly, so the view has no `useSearchParams` and no Suspense boundary, and the RSC payload carries plain server-rendered markup. Note that the visible body still arrives through that payload rather than the initial HTML: `notFound()` throws `NEXT_HTTP_ERROR_FALLBACK;404` and Next.js serves the not-found tree through its HTTP access fallback.
- Portfolio pages keep the header's repository and documentation links. `SiteHeader` treated its children as a replacement for the default links, so every profile page had no way back to the project's source; route-specific controls are now passed as `actions` and rendered alongside the links.
- `next/image` can no longer be handed an avatar host that is not allowlisted, which threw and took down the entire portfolio. `images.remotePatterns` now covers the hosts GitHub actually returns, and an unknown host falls back to an initial-letter avatar that cannot fail.
- Featured-language bars are no longer blank when printed. Browsers strip background gradients, so the print stylesheet now renders the track and fill as flat greys with borders while the numeric percentage stays legible.
- Several near-white elements printed as invisible white-on-white, including repository names rendered as `div`s, the search submit button and the muted placeholder text. They are now forced to legible colours in print media.
- The share toast now dismisses itself and can be closed by hand, instead of staying on screen until the next click. Stale timers are cleared on re-share, manual dismiss and unmount.
- HSTS no longer advertises the `preload` directive. It is only meaningful once the domain is actually registered on the browser preload list.

### Changed

- Every social card is redrawn in the same identity as the site: night navy ground, off-white ink, signal-yellow rules, mono labels and a titleblock strip. The profile card's portrait is a square plate with a yellow frame rather than a circular medallion.
- The social card keeps the starred ranking instead of the pinned list. A card is requested for every share of a profile URL, and the pinned lookup needs a GraphQL token that a card request should not depend on, so the titleblock copy stays neutral about how the three named repositories were chosen.
- Corner radii across the component classes (`card-premium`, `input-premium`, `btn-primary`, `pill-btn`, `logo-mark`, `step-number`, `stat-pill`, `profile-avatar`) are 2px, and the `rounded-*` utilities were stripped from the header, the theme toggle, the language picker, the search form, the 404 sheet, the error boundary and both pages, so the stylesheet is the only place the decision lives. The portrait on the profile card keeps its deliberate 2px plate.
- The portfolio page's screen-only context strip and footer are drawn as sheet annotations: the mobile login chip is a stamped square rather than a pill, the page title is set in the same heavy grotesk as every other heading, and the footer is a framed titleblock strip instead of a centreed line under a fading rule.
- The repository half of a portfolio page streams in behind a `<Suspense>` boundary of its own. The person, the header and the footer are in the first chunk with a skeleton in the space the projects will take; the six repositories, the featured languages and the `ProfilePage` data block that describes them arrive in the last. The featured languages moved out of the profile card into their own `FeaturedLanguages` component for the same reason: the data they are derived from is the data the boundary streams, so a block that needs it cannot sit in the shell. The two blocks are now one detail of the sheet instead of the card's own tail.
- The print stylesheet is now designed for paper rather than inherited from the screen. It sets `@page` margins, rebases headings in points so they scale with the 11pt body instead of rendering a 36px name at roughly 27pt, cuts the vertical rhythm in millimetres, pins the repository grid to two columns instead of letting the paper width decide, releases the three-line description clamp, keeps headings off the foot of a page, and prints the portfolio URL, which a sheet of paper cannot show on its own.
- The screen-only context strip above the profile card is no longer printed, so a printed page opens with the person's name. Everything it said is repeated by the profile card and the footer.
- `NEXT_PUBLIC_SITE_URL` and `NEXT_PUBLIC_GITHUB_REPO_URL` are now `SITE_URL` and `GITHUB_REPO_URL`. Both values are only ever read by Server Components and metadata routes, so the `NEXT_PUBLIC_` prefix only served to inline them into the client bundle and to trip Vercel's public-variable confirmation. The old names are still read, so an existing deployment keeps working.
- Repository requests ask for the number of repositories the page displays instead of always requesting 100. The Open Graph image previously downloaded 100 repository objects to use three.
- The advertised version is kept in sync with `package.json` by a test instead of being hardcoded as `v1.0`, and the copyright year is derived from the current date.
- The example descriptions are keyed through an explicit `descriptionKey` in `lib/examples.ts`, so a missing translation in any of the four locales is a compile error rather than a silently wrong string.
- Sitemap entries no longer claim a build-time `lastmod`, which told crawlers every page changed on every deploy, and now carry absolute hreflang alternates for all four locales plus `x-default`.
- The application error boundary wraps its `useSearchParams` consumer in a Suspense boundary, so the route can be statically rendered later without silently falling back to client rendering.
- Added an MIT `LICENSE` file and a matching `license` field in `package.json`.

### Removed

- Dead code: the unused `profile.avatarTitle` dictionary entry in all four locales (the verification badge that read it is gone), the duplicated GitHub failure describer on the portfolio page (the data layer exports one helper now), and the dead `.orb` decorative layers on the home page, the 404 and the error boundary. The home page no longer marks its middle step as featured: the `.featured-card` edge claimed a hierarchy the three steps do not have, and no three identical cells are more equal than that. The class itself stays in the stylesheet for now.
- Dead code: the unused `metadata.fallbackDescription` and `header.info` dictionary entries in all four locales, the unused non-localized `formatDate` in `lib/skills.ts` that duplicated `RepoGrid`'s localized formatter, the hardcoded Turkish `description` field in `lib/examples.ts`, the unreferenced `.print-break-before` print class, the `favicon.ico` matcher exclusion for a file the project does not have, and the Playwright entries in `.gitignore` for a runner the project does not use.

### Security

- The avatar badge no longer combines a `title` attribute with `aria-hidden`, and repository star and fork metadata no longer duplicate their labels for screen readers.
- The search input now describes itself with the example usernames, so the `github-examples` block is no longer an orphaned id.

### Added

- A theme toggle in the header, and deep-navy night as the default palette. Only the exact cookie value `light` selects the paper inversion; a missing or hand-edited cookie falls back to night, so the server always renders a complete class on `<html>` before the first paint instead of flashing the wrong one.
- Pinned repositories come first. `pinnedItems` is GraphQL-only, so the lookup is enabled by `GITHUB_TOKEN` and answers `null` for every failure — no token, auth, rate limit, timeout, unexpected shape, or nothing pinned — and the page falls back to the starred ranking, which is the list a tokenless deployment has always shown.
- Repository topics on each project cell, framed like the figure row and set in the same mono face: on a drawing a tag and a figure are both annotation.
- A streamed loading skeleton for the repository block of the portfolio page, shaped like the projects it stands in for (three tolerance rows, six project cells), coloured with tokens only so one set of values works in both themes, and localized from the locale the page already resolved instead of from the request header. It is never printed, and it ships no client JavaScript.
- Blueprint identity across the home page, the 404s, the error boundary and both social cards: hairline-bordered sheets, sheet-head strips, spec tables, mono cell references (`S.01`, `B.01`), titleblock footers, and one 2px radius in the stylesheet that no component overrides.
- Vercel Web Analytics on every document, imported from `@vercel/analytics/next` so a page view is attributed to the route pattern (`/`, `/[username]`) instead of the raw path, which here is a user-supplied username and would otherwise explode the dashboard's cardinality. It renders no markup, and the existing nonce-based Content-Security-Policy needs no change: the script is injected by the nonce'd Next.js client bundle, which `strict-dynamic` already trusts, and the beacon posts same-origin to `/_vercel/insights/view`, which `connect-src 'self'` already allows.
- JSON-LD structured data, localized per request. The root layout describes the product once as a `WebSite` and a `WebApplication` (free offer, no account, `inLanguage` for the reader's language), the home page describes its own visible "how it works" section as a `HowTo` built from the same `home.steps` strings it renders, and a portfolio page describes the person as a `ProfilePage` with a `Person` main entity, the six displayed repositories as `SoftwareSourceCode` and their languages as `knowsAbout`. Only facts the page shows are emitted, and the person's entity id is the locale-free URL, so the four languages describe one person rather than four. The GitHub account's creation date is deliberately left out of the `ProfilePage`: `WebPage.dateCreated` is when the page was created, this page is generated per request, and the page never shows an account date — publishing it would claim a portfolio written today was written in 2011. Payloads are escaped so a repository description or a bio containing `</script>` cannot close the data block.
- Per-language `keywords` for the home page and for each portfolio page, in all four languages, with the person's name in the profile set.
- `og:locale:alternate` on both routes, so Facebook, LinkedIn and Slack pick the card that matches the language of the page being shared instead of always the default one.
- The owner's profile is submitted in the sitemap, so it is discoverable in search rather than only linked from the home page. The sitemap keeps its own list instead of projecting `EXAMPLES`: the example grid is a UI decision about what to showcase, the sitemap is about what we want crawled, and the profiles that are no longer showcased stay in the sitemap for long-tail discovery.
- The site owner leads the home page example grid and the example links under the search box, described in all four languages. The example grid is capped and centred at two cards so it does not sprawl.
- Accessible profile sharing through the native Web Share API, with localized Clipboard API fallback and visible error feedback.
- Generated `app/manifest.ts` and web app identity metadata.
- Locale-aware canonical/hreflang metadata, `x-default`, localized 404/error screens and a generated web application manifest.
- Coverage thresholds, CI artifacts, route/component tests and GitHub data-layer edge-case tests.
- Self-hosted Inter and JetBrains Mono font assets.
- Per-request production CSP nonces and stricter environment/security documentation.
- Vercel Web Analytics, mounted once in the root layout. The `next` entry point is used rather than the bare React one so a page view is attributed to its route pattern (`/`, `/[username]`) instead of the raw path: every portfolio is at a user-supplied URL, so reporting raw paths would give the dashboard one row per visitor-supplied string. The nonce-based policy needed no change. The script is created with `document.createElement` from the Next.js client bundle, which is itself the nonce'd script, so `'strict-dynamic'` trusts the injected tag even though it carries no nonce; and the beacon is posted to the same-origin `/_vercel/insights/view`, which `'connect-src self'` already covers.

### Changed

- Social card images are generated per language. Both metadata image routes use `generateImageMetadata`, so the four languages are four distinct URLs (`/opengraph-image/<locale>` and `/<username>/opengraph-image/<locale>`) instead of one shared response: a social crawler that drops the page's query string still gets a rendered card, each language is a separate cache entry, and the home page's cards are prerendered at build time. The card is addressed in the path rather than by a query parameter precisely because crawlers fetch the image on its own.
- Both routes declare their card explicitly, with a localized `alt` and the real dimensions. Next injects a metadata image route's generated images into any page below it that does not name an image itself, which would have put four languages' cards on every page and on both 404 segments.
- Sitemap entries are now one per language instead of one per page. A localized URL that is only reachable as an alternates href of its siblings is discovered late, if at all; each entry repeats the full hreflang cluster, as the protocol asks.
- SEO metadata is built in one module, `lib/seo.ts`, so the two routes cannot drift apart on canonicals, hreflang, social cards, keywords, indexing directives or structured data. The duplicated `getMetadataAlternates`/`getCanonicalUrl` helpers and the hand-rolled Turkish description and keyword list in the root layout are gone; the layout now reads the same default-locale dictionary the rest of the site does.
- The blog URL normalizer used by the profile card moved to `lib/site.ts` as `getSafeExternalHttpUrl`, so the structured data and the visible link agree on what is a safe external address.
- `getProfileOpenGraphImagePath()` takes the locale, and `getProfilePathname()` centralizes the percent-encoded profile pathname that links, canonicals, hreflang sets, the sitemap and the image paths all derive.
- Featured language percentages are now calculated from the same six repositories displayed to users.
- GitHub requests normalize usernames before network access, retry transient timeouts/network failures and protect quota-sensitive Open Graph generation with short response caching.
- Site URL validation rejects credentials, query strings, fragments and unsafe paths.
- Profile Open Graph images use one language-independent design and a stable metadata image path.
- Next.js 16 image loading now uses the current `preload` API instead of deprecated `priority`.
- CI runs generated route types, coverage checks and production dependency auditing on Node.js 20 and 22.
- README documentation now covers sharing, manifest behavior, environment responsibilities, tests and the complete quality gate.

### Security

- Added a nonce-based Content Security Policy for production while retaining the development requirements needed by React and HMR.
- Preserved clickjacking, MIME-sniffing, referrer, permissions and HSTS protections.
